# Техническое задание: Discord-бот для системы АФК

## 1. Общая задача

Необходимо разработать полноценного Discord-бота на **Python** для управления системой АФК (отсутствия игроков) на небольшом Discord-сервере примерно на 20 человек.

Бот должен позволять обычным участникам сервера:

1. Создавать заявку на АФК через удобную Discord-форму.
2. Указывать дату и точное время окончания АФК.
3. Указывать причину отсутствия.
4. Отслеживать статус своей заявки.

Пользователям с определёнными Discord-ролями бот должен позволять:

1. Просматривать новые заявки.
2. Принимать заявки.
3. Отклонять заявки.
4. При отклонении указывать причину отказа.
5. Управлять активными АФК.
6. Просматривать общую таблицу текущих АФК.

Бот должен автоматически отслеживать время окончания АФК и завершать их.

---

# 2. Технологический стек

Использовать:

- Python 3.11+
- `discord.py 2.x`
- SQLite для хранения данных
- `python-dotenv` для переменных окружения
- asyncio для фоновых задач
- Discord Buttons
- Discord Modals
- Discord Embeds
- Discord Slash Commands

Не использовать веб-сервер, если он не требуется.

Бот должен работать как обычный Discord bot process.

# 7. Форма создания АФК

Modal должен содержать минимум два поля.

### Поле 1

Название:

```text
Дата и время окончания АФК
```

Placeholder:

```text
10.08.2026 18:30
```

Формат:

```text
DD.MM.YYYY HH:MM
```

### Поле 2

Название:

```text
Причина АФК
```

Placeholder:

```text
Учёба, отпуск, личные обстоятельства и т.д.
```

Поле должно поддерживать достаточно длинный текст.

---

# 8. Валидация времени

Бот должен самостоятельно проверять введённую дату.

Допустимый формат:

```text
DD.MM.YYYY HH:MM
```

Например:

```text
10.08.2026 18:30
```

Если пользователь ввёл неправильный формат:

```text
❌ Неверный формат даты.

Используйте:

DD.MM.YYYY HH:MM

Пример:
10.08.2026 18:30
```

Если указанное время уже прошло:

```text
❌ Нельзя создать АФК до времени, которое уже прошло.
```

Также необходимо учитывать часовой пояс сервера.

Часовой пояс вынести в `.env`:

```env
TIMEZONE=Europe/Berlin
```

Все даты хранить в UTC, а пользователю показывать в настроенном часовом поясе.

# 13. Принятие заявки

7. Выдать пользователю роль АФК.
8. Обновить Embed заявки.
9. Обновить таблицу активных АФК.
10. Отправить пользователю уведомление.

```text

```

Например:


После окончания АФК бот должен автоматически снять эту роль.

Если роль уже существует — не создавать новую.

# 17. Автоматическое обновление таблицы

Таблица должна автоматически обновляться:

- после создания заявки;
- после принятия заявки;
- после отклонения;
- после окончания АФК;
- после отмены АФК;
- после удаления пользователя с сервера;
- после перезапуска бота.

Не создавать новое сообщение каждый раз.

Бот должен хранить:

```text
AFK_STATUS_MESSAGE_ID
```

и редактировать существующее сообщение.

Если сообщение было удалено — бот должен автоматически создать новое.

# 18. Автоматическое завершение АФК

Бот должен иметь background task/scheduler.

Например, каждые 30–60 секунд проверять:

```text
SELECT * FROM afk
WHERE status = 'APPROVED'
AND end_time <= current_time
```

Для каждой такой записи:

1. Изменить статус на `EXPIRED`.
2. Снять AFK-роль.
3. Обновить таблицу.
4. Обновить исходную заявку.
5. Записать событие в лог.

Пользователю отправить:

```text
⏰ Ваш АФК завершён.

Вы больше не числитесь в АФК.
```

Если отправка DM невозможна, не считать это критической ошибкой.

# 27. Защита от ошибок

Обязательно обработать:

- пользователь удалён с сервера;
- пользователь покинул сервер;
- пользователь уже имеет AFK-роль;
- AFK-роль была удалена;
- канал был удалён;
- сообщение заявки было удалено;
- сообщение таблицы было удалено;
- бот был перезапущен;
- база данных существует, но некоторые записи повреждены;
- Discord API временно недоступен;
- пользователь дважды нажал кнопку;
- два модератора одновременно пытаются обработать одну заявку.

Особенно важно избежать ситуации:

```text
Moderator A → принимает
Moderator B → тоже принимает
```

Второе действие должно получить:

```text
⚠️ Эта заявка уже обработана.
```
